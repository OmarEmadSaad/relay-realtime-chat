About this project

Relay is a full-stack messaging app: an Express 5 REST API and a Socket.IO server share one Node.js process and one MongoDB database. Everything is TypeScript, and this UI is compiled to plain JavaScript modules with no framework.

Why Socket.IO instead of polling?

Polling asks "anything new?" every few seconds, so messages arrive late and most requests return nothing. A Socket.IO connection stays open, so the server pushes each message, typing indicator and presence change the moment it happens, and falls back to long-polling when WebSockets are blocked.

How the pieces fit

  • REST handles login, conversation lists and paginated history.
  • Socket.IO carries live events: message:send, message:new, typing:start, presence:update, message:read…
  • Authentication: the socket handshake carries the JWT access token. The server verifies it, loads the user and never trusts ids sent by the client.
  • Authorization: every join, send, read and history request checks conversation membership in MongoDB. Knowing a room id is not enough.
  • Rooms: each socket joins a personal user:<id> room, so messages reach all of a member's tabs and devices. A conversation:<id> room carries typing indicators for whoever has that chat open.
  • Persistence: messages are stored in MongoDB with a compound index for history pages and a unique (sender, clientId) index so retries never create duplicates.
  • Presence counts sockets per user, so closing one of two tabs doesn't mark you offline.

The README in the repository covers the full architecture, event reference and the trade-offs behind it.
